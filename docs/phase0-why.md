## ① Tokenizer 的三角权衡 ✅

同一份 tinyshakespeare（1,115,394 字符）实测：

| 方案 | 词表 | 序列长度 | 字符/token | 嵌入层参数(d=384) |
|---|---|---|---|---|
| char-level | 65 | 1,115,394 | 1.00 | 24,960 |
| word-level | 13,331 | 262,927 | 4.24 | 5,119,104 |
| BPE (GPT-2) | 11,706 | 338,025 | 3.30 | 4,495,104 |

**word-level 为什么被淘汰**
1. **无闭包性**：词表是封闭集合，遇到表外词就没法编码
2. **长尾学不动**：45.3% 的词在整个语料里只出现一次，这些 embedding 被更新一两次就等于随机向量

**BPE 与 char-level 共有的关键性质 = 闭包性。** BPE 底层是 256 个字节，任何输入最坏退化成逐字节，**永不 OOV**。实测：`zxqwvbnm`、日文汉字都能切。

**序列长度的代价不是线性的。** 每层两项：线性项 `O(n·d²)`（QKVO 投影 + FFN）与二次项 `O(n²·d)`（QK^T 和加权求和），比值 = `n/d`。
- `n < d` 时线性项主导 —— 我们跳 1 的配置 n=128/d=128 就在这个区间
- `n >> d` 时二次项统治 —— 这是 FlashAttention / PagedAttention 存在的理由

**小模型必须用小词表，真正原因是参数预算**，不是速度：BPE 的嵌入层 450 万参数，比我们跳 1 整个模型（82 万）还大 5 倍，模型会退化成"巨大查找表 + 一丁点 Transformer"。

**char-level 的真实代价是看得短。** 同样 `block_size=256`，char 只能看到 256 个字符（约两行台词），BPE 能看到 ~850 字符。这是跳 2 换 BPE 的真实动机。

**副产品**：`strawberry → st|raw|berry`。模型看到的是 3 个整体符号，根本看不到字母 —— 问它有几个 r 不是在让它数数，是在让它回忆。

## ④ 因果掩码 → KV cache ✅

### 实证：掩码的单向性是严格的

改动 t=4 之后的 token，输出差异：

```
位置 :       0       1       2       3       4       5       6       7
差异 :  0.0000  0.0000  0.0000  0.0000  0.4214  0.8671  0.6083  0.7210
```

不是"近似单向"，是 softmax 对 `-inf` 得到的**严格零权重**。

### ④-a 为什么训练能并行

两个条件缺一不可：

1. **位置间无计算依赖**。RNN 的 `h_t = f(h_{t-1}, x_t)` 是一条长度 T 的串行链 —— 注意 RNN 在 **batch 维度上照样能并行**，它废掉的是**序列维度**。Transformer 里位置 i 直接从 `x_0..x_i` 算出，依赖链长度为 1。
2. **Teacher forcing**：训练时喂真实的下一个 token，不是模型自己的预测，所以 T 个位置的输入全部提前已知。

代价：训练时永远看到完美上文，推理时看到自己生成的（可能有错的）上文 —— 这就是 **exposure bias**。

### ④-b 无 cache 浪费多少

生成 400 token（block_size=256 封顶）≈ 69,760 次 token 前向 vs 400 次，约 **174 倍**。`O(N²)` 对 `O(N)`。

### ④-c 为什么缓存 K/V 不缓存 Q —— 判据是"复用性"不是"不可变性"

常见错误答案："旧的 K/V 不会变所以要缓存"。但**过去位置的 Q 同样不会变**，这个判据区分不开两者。

真正的判据：

```
第 t 步只算注意力矩阵的一行：  q_t · [k_0, k_1, ..., k_t]
                               ↑        ↑
                       只要当前这一个   要全部历史
```

- **K/V 是被查询的对象** —— 每步都要用上全部历史，必须留
- **Q 是查询本身** —— `q_3` 的唯一使命是算出位置 3 的输出，那个输出早就吐出去了，此生再无用处

### 实现验证

- greedy 解码下有无 cache 输出**完全一致** ✅
- 故意去掉位置嵌入偏移：**不报错、不崩溃**，只是安静退化成重复文本。KV cache 的 bug 全是这个形态，所以"有无 cache 等价"这个测试不能省。

### KV cache 的显存代价 → Phase 6

```
Llama-2-7B fp16：每 token = 2(K/V) × 32层 × 4096维 × 2字节 = 512 KB
                4096 上下文 = 2 GB —— 单个请求
```

80GB A100 扣掉 14GB 权重，剩下全给 KV cache 也只够 33 个并发。两条应对路线：
- **GQA / MQA** —— 多个 Q 头共享一组 K/V 头
- **PagedAttention** —— 请求长度不可预知，按 max_len 预分配会大量浪费；切成固定块按需分配，**就是操作系统的虚拟内存分页**。我们 `KVCache` 里用 concatenate 每步重分配，正是它要解决的问题

## ⑥ Pre-LN vs Post-LN ✅

```
Pre-LN    x + f(LN(x))        ∂x_{l+1}/∂x_l = I + J_f
                              ↑ 恒等矩阵 = 不经任何变换的梯度直通车
                              L 层连乘 ≈ I + ΣJ_f，尺度与深度基本无关

Post-LN   LN(x + f(x))        ∂x_{l+1}/∂x_l = J_LN · (I + J_f)
                              ↑ 每层梯度都要再过一次 LN 雅可比
                              L 层连乘 = ΠJ_LN · (...)，随深度指数变化
```

**Pre-LN 的代价（少有人提）**：残差流方差随层数累加，越深的层 `f(LN(x))` 相对 `x` 越小，**深层被稀释，等效深度小于名义深度**。这是 DeepNorm / Sandwich-LN 出现的原因，也是 Pre-LN 模型末尾必须补 `ln_f` 的原因。

## ⑧ warmup 的作用 ✅ —— 2×2×2 对照实验

12 层 / n_embd=128 / 300 steps / 无 dropout / 固定种子 / **恒定 lr**（干净对照，只有前 50 步不同）

| 配置 | s10 | s25 | s50 | s100 | s299 | 峰值 |
|---|---|---|---|---|---|---|
| Pre-LN　warmup　lr=1e-3 | 3.365 | 3.316 | 2.722 | 2.546 | **2.125** | 4.229 |
| Pre-LN　no-warm　lr=1e-3 | 3.361 | 3.357 | 3.263 | 2.950 | 2.515 | 4.229 |
| Post-LN warmup　lr=1e-3 | 3.224 | 2.837 | 2.563 | 2.468 | **1.975** | 5.333 |
| Post-LN no-warm　lr=1e-3 | 3.387 | 3.355 | 3.273 | 3.302 | 3.328 💀 | 5.308 |
| Pre-LN　warmup　lr=6e-3 | 3.382 | 3.251 | 2.845 | 2.660 | 2.547 | 4.229 |
| Pre-LN　no-warm　lr=6e-3 | 3.618 | 3.367 | 3.273 | 3.277 | 2.757 | 4.343 |
| Post-LN warmup　lr=6e-3 | 3.390 | 3.369 | 3.300 | 3.314 | 3.329 💀 | **7.096** |
| Post-LN no-warm　lr=6e-3 | 3.625 | 3.376 | 3.272 | 3.301 | 3.327 💀 | 4.264 |

`≈3.33` 是**模型塌缩值**（退化成输出字符边际频率），不是"训得慢"。

**结论**

1. **warmup 的作用是防止早期不可逆损伤，不是加速收敛。** 所有 no-warmup 组在 s10~s50 都趴在 3.26~3.36 附近 —— 头几步大梯度把模型推进了退化状态。Pre-LN 能爬出来（残差直通车保证梯度还传得动），Post-LN 爬不出来。
2. **Post-LN 在 lr=6e-3 下两组都死**，warmup 也救不回来（峰值 7.096 说明它先炸了再塌）。
3. **Pre-LN 的真正价值是把可用学习率的范围拉宽了**，不是"效果更好" —— 注意 Post-LN + warmup 在 lr=1e-3 下拿到了全场最好的 1.975。大模型时代要大 batch + 大 lr，Post-LN 那个窄窗口不够用。

**方法论教训（两次踩同一个坑）**
- 第一版对照里 `--no-warmup` 不只去掉了 warmup，cosine 衰减也从 step 0 开始，**整条 lr 曲线都变了**。改成恒定 lr 重做才干净。（结论没变：cosine 版差 0.36，恒定版差 0.39）
- KV cache 规模实验里同时改了 `n_layer` 和 `n_embd`，得到非单调的假象。固定层数重测才单调。

## 附加发现 · 解码是 memory-bandwidth-bound（Phase 6 的地基）

### KV cache 实测加速比远低于理论值

| 生成长度 | 无 cache | 有 cache | 加速比 | 理论 |
|---|---|---|---|---|
| 32 | 0.030s | 0.017s | 1.7x | 16.5x |
| 255 | 0.607s | 0.185s | **3.3x** | 128x |

固定 n_layer=8 只变宽度，加速比 2.5x → 3.6x 后饱和。原因不是实现问题：

### 每生成 1 个 token，必须把全部权重从内存读一遍

| 参数量 | 权重(fp32) | 每步 | 实测带宽 | 占 M4 Pro 峰值 273 GB/s |
|---|---|---|---|---|
| 6.4M | 26MB | 0.58ms | 44 GB/s | 16% |
| 25M | 102MB | 0.89ms | 114 GB/s | 42% |
| 57M | 228MB | 1.48ms | 154 GB/s | 56% |
| 101M | 404MB | 2.18ms | **185 GB/s** | **68%** |

模型越大越贴近带宽天花板。**KV cache 消掉的是计算量，而解码的瓶颈不是计算量。**

- **Prefill**（一次算 T 个位置）→ compute-bound
- **Decode**（一次算 1 个位置，权重照读不误）→ **memory-bandwidth-bound**

这是 TTFT 和 TPOT 必须分开看的根本原因。

### 从第一性原理预测 14B 模型的速度 —— 并验证

```
理论上限 = 内存带宽 / 权重大小 = 273 GB/s ÷ 9 GB = 30.3 tok/s
按实测 68% 效率预测          ≈ 20 tok/s
ollama deepseek-r1:14b 实测   = 22.29 tok/s   (带宽利用 201 GB/s = 73%)
误差 10%
```

**推论（Phase 6 待验证）**
- 量化加速解码，是因为要读的字节变少了，不是因为算得快 ⚠️
- 批处理近乎免费：同一份权重读一次，可以服务多个请求 → **continuous batching** ⚠️
- MoE 有效，是因为每 token 只需读激活的专家 ⚠️
